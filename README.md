# Financial Literacy Lab｜我的理財實驗室

用目標、時間、現金流與假設，看懂自己的財務選擇。

Financial Literacy Lab 是繁體中文、以新臺幣為預設單位的財務教育網站，提供四個可獨立使用的工具：**目標倒推、長期複利、家庭預算、退休提領**。手機與桌機皆可操作，免登入、不需連接銀行帳戶，也不串接即時行情。

理財不是一味減少消費，也不是讓支出比例符合標準。本站希望先協助使用者理解家庭安全與現金流，再思考長期目標及生活品質。試算是條件情境，不是報酬預測、投資推薦或退休安全認證。

## 快速開始

1. 從首頁選擇一個工具，填入自己的數據或先調整示範值。
2. 先看主要結果，再展開詳細分析、進階設定與風險說明。
3. 需要跨工具比較時，使用明確的「帶入」按鈕；切換工具不會自動同步或覆寫另一頁的參數。
4. 每個工具可複製摘要與重設示範值。家庭預算及退休規劃另可複製 AI 分析 Prompt，自行貼到 ChatGPT／Gemini。

數字可用千分位及小數輸入。編輯中空白或無效值會暫留最近有效結果，完成輸入後提示錯誤；暫留畫面不是新草稿已驗證的結果。來源草稿未完成或超界時，相關帶入按鈕會停止帶入。一般單欄金額上限為 NT$ 1 兆，總結果仍可能較大；超過退休起始資產上限的複利結果不得帶入。

## 四大核心功能

### 1. 目標倒推

想知道「希望 N 年後累積到某個金額，現在每月需要投入多少」時使用。

- 填入目標資產、1～40 年期間、假設年化總報酬率，以及起始市值。
- 起始資產可直接輸入市值，或以最多三檔 ETF 的股數 × 參考價格計算；兩種來源互斥，不相加。
- 可開啟兩階段投入，先指定第一階段金額，再反推之後的月投入。
- 顯示所需月投入、起始資產、新增本金、假設收益及同條件銀行存款比較，並提供圖表與逐年數據。

反推的月投入向上取整至元；若目前資產在假設下已能達標，所需新投入為 0，不代表現實中一定能達標。

### 2. 長期複利

想知道「每月投入一筆錢，未來可能累積多少」時使用。

- 設定起始市值、月投入、1～40 年期間與假設報酬率；可指定中途增加或減少月投入。
- 比較投資、銀行存款與本金，查看 10／20／30 年及自訂終點、完整／聚焦圖軸與逐年明細。
- 「如果晚 10 年才開始？」實際比較未延後、延後 5／10 年的可用情境。延後方案投入本金不同，不能將全部差距歸因於複利。
- 展開「多存一點，未來差多少？」比較原方案 A 與額外月投入 B。B 在中途調整前後都增加同一額外金額；不修改原方案或家庭預算。
- 可將 A 或 B 的完整期末資產帶入退休提領，採取代而非相加；另標示方案、累積年數與未來名目資產的時間基準。

未來期末資產不是今天已持有的資產，亦不能直接視為今天生活費的購買力。

### 3. 家庭預算

整理日常收支、貸款、投資與生活目標，先看每月及每日的可支配餘額。

- **收入互斥來源：** 月薪模式為固定實領月薪＋年度獎金；年薪模式為已含獎金的全年實領總額，不重複加計隱藏月薪或獎金。另列其他每月固定收入。
- **投資現金收入：** 可選不納入、納入預算（月平均）或再投入，來源互斥，不含未實現價差；股息不保證。
- **生活費：** 快速模式使用必要／非必要兩個總額；明細模式使用 19 項生活費，可調整必要／非必要分類。兩組資料保留，但只採目前來源，不相加。
- **貸款與目標：** 房貸、車貸、信貸、其他貸款各有月付額與剩餘期數。大型購物可指定期限或指定月存，另有旅遊基金與其他儲蓄。
- **視覺化：** 七類資金流向環圈、收支健檢、逐月／逐年預測及自訂未來收入／生活費變動。其他儲蓄獨立扣款並列對帳，不硬塞為第八個切片。
- **財務安全：** 緊急預備金及退休儲蓄自評只代表使用者自我確認，不是系統查證或資金達標認證。

ETF 輸入的月金額會完整扣除一次；若無法負擔，保留負結餘並提示，不自動降低投入。家庭圖表是預算現金流，**不是累積現金資產**；未分配結餘不自動視為已儲蓄或現金過多。

在健檢區按「帶入長期複利試算」，只取代複利月投入並設 30 年，保留起始資產與報酬率，停用舊的中途投入設定。帶入後仍可自行編輯，不自動同步。

#### 依收入推薦的參考預算模式

收入區預設「依收入自動推薦」，也可自由選擇四種手動模式：

| 模式   | 必要支出 | 品質生活 | 儲蓄投資 |
| ------ | -------- | -------- | -------- |
| 經典   | 50%      | 30%      | 20%      |
| 基礎型 | 55%      | 25%      | 20%      |
| 平衡型 | 45%      | 30%      | 25%      |
| 品質型 | 35%      | 35%      | 30%      |

自動推薦採同一有效家庭稅後月平均收入 × 12 年化，含選擇納入的其他收入，不把月薪與年薪再次相加：

- 低於 NT$ 120 萬：基礎型。
- NT$ 120 萬以上、未滿 240 萬：平衡型。
- NT$ 240 萬以上：品質型。

修改收入時，自動模式立即更新參考比例及月參考金額；手動模式保留選擇，只更新金額，直到使用者重新選自動。收入未完成、無效或非正數時，自動暫用經典並提示；手動選擇仍保留，暫停比例判定與參考金額。

這些是教育性參考，**不是支出上限、必須花完的額度、強制儲蓄額或官方統計標準**。經典模式保留 CFPB 50／30／20 參考背景，其餘比例與收入門檻是本站設計。合理生活品質不應只因分類或比例就被要求削減。

卡片使用未四捨五入的原始比例：必要／品質生活高於目前目標為粉紅，未超過為一般；儲蓄低於 10% 為黃，其他為一般。顏色不受其他卡片或是否赤字影響；超過比例本身不證明有財務危機或必須減支。細項比例也只是可調的情境參考。

### 4. 退休提領與進階退休／轉職規劃

原提領工具可用起始資產推算提領金額，或用每月需求缺口倒推概念性起始資產。

- 提領策略包括固定實質、當期比例與固定名目；可設定名目報酬、通膨、退休起始年齡與期間。
- 顯示實際可提領金額、名目／實質剩餘資產、首次不足或耗盡、策略比較及人工報酬順序風險示範。
- 逐年明細包含年度／年齡、實際提領、累積提領、剩餘資產。未實際領到的需求不計入累積提領。

原試算下方的「進階退休與轉職規劃（選填）」預設收合，全空白不影響原提領試算。可填個人與職涯、今天資產與月投入、家庭責任、各筆給付或收入；**離開原工作與完全退休分開設定**。時間可用西元、民國或年齡，民國年加 1911；年齡以目前年度近似換算，未處理生日。

「帶入家庭預算資料」由使用者點擊，取代對應生活費、投資、其他目標與貸款，並附完整家庭摘要；配偶收入及是否持續等資訊需另行確認。重新點擊才再次覆寫，不反向寫回家庭預算。

資料足夠時，可指定年份（未填採離職年）比較基本生活與維持儲蓄目標的最低稅後工作月收入。給付有每月／一次性、開始／結束時間及確認狀態；未確認給付不列確定月收入，一次性給付不作永久月收入，也不自動加進資產。不憑軍人、原住民或其他身分推斷資格、金額及能否併領；自住房屋不視為可花的退休現金。

這是**指定年份的簡化月平均缺口**，不是完整逐年退休精算：起訖年份整年有效、貸款最後一年仍扣款，不自動推估教育費、調薪、通膨或安全退休年齡。資產、原提領結果與未來複利資產不自動補此缺口；缺資料就列出原因，不把空白當 0。

## AI 理財教練：複製後自行貼到 ChatGPT／Gemini

本站只整理資料及產生 Prompt，**不在站內呼叫 AI API，也不直接產生 AI 回答**。

1. 填好家庭預算，選擇「財務健康檢查」「消費與預算調整」或「ETF 投資規劃」。退休頁另有「AI 退休與轉職規劃」。
2. 點擊「複製 Prompt」，檢查剪貼簿內容，再自行貼到所選 AI 服務。
3. 家庭三主題指令要求以繁中、新臺幣、三個簡短編號／條列及可調整的小標題回答，約 150～250 字；不產生表格、圖表、程式碼區塊或長篇演算。完整輸入不因回答字數而刪減。
4. 退休／轉職任務含完整有效退休試算、已填進階資料、主動帶入快照及未知資訊，目標約 250～400 字，必要時可比較情境；與家庭三主題的短答格式不同。

分析原則先看安全、現金流與債務，再看退休／儲蓄與其他目標，最後尊重生活品質與自主選擇。固定月薪、年度獎金與年均月額必須分開；全年沒有赤字不代表每月沒有壓力。孝親與親屬支援應評估負擔、實際需求及分擔，不一律視為不可調整，也不臆測情緒勒索或直接建議停止扶養。有合理調整空間時才談長期機會成本，不為展示複利而硬找減支。

複製時有等待／成功／失敗提示。AI 教練剪貼簿失敗會保留待複製全文，供手動選取；普通工具摘要複製失敗則提示選取結果文字。AI 平台可能不完全遵循指令或算錯數字，請自行核對；未知資料、使用者自評與未確認給付不能變成確定事實，法規請查主管機關最新官方資訊。

## 計算公式、時間基準與限制

以下對應 `src/lib/finance.ts`、`budget.ts`、`retirementPlanning.ts` 的現行實作；不是歷史回測或精算承諾。

### 投資累積與目標倒推

- 有效年化總報酬率 `R` 換算月率：`r = (1 + R)^(1/12) - 1`。
- 每月底投入 `C_m`：`V_m = V_(m-1) × (1 + r) + C_m`。銀行採相同起點、投入時點及月率換算。
- 固定月存、期間 `n`、起始資產 `P` 時，目標 `T` 的未取整月存為 `max(0, (T - P × (1+r)^n) / F)`，其中 `F = ((1+r)^n - 1) / r`；`r = 0` 時 `F = n`，最後向上取整至元。兩階段沿用相同累積函式後反推剩餘期間。
- 累積本金含起始市值與未來投入；假設收益是期末市值減累積本金，不是持股的歷史已實現獲利。
- A／B 額外資產差為 B 期末資產減 A；教育性首年月平均提領差為「差額 × 4% ÷ 12」，不是保證退休收入。

投資／目標累積預設 8%、銀行預設 1.5%，均可修改且只是教育性假設；總報酬已含股息，不另加配息。累積結果未自動折算通膨，不代表今天購買力。晚開始比較的本金不同；相同總本金的公平比較尚未實作。

### 家庭預算與目標

- 工作年收入：月薪模式為「固定月薪 × 12＋年度獎金」；年薪模式直接使用含獎金總額。規劃月平均為年收入 ÷ 12，不代表獎金實際入帳月份。
- 家庭月收入另加其他固定月收入，以及僅在「納入」時的年度投資現金收入 ÷ 12。
- 月結餘＝月收入－生活費－當期貸款－購買後持有成本－購物月存－旅遊基金－ETF－其他儲蓄。每天平均依該月實際天數換算，年度預測由逐月資料加總。
- 貸款第 N 期仍扣款，第 N+1 期停止。購物期限模式按剩餘資金／期數向上取整月存；固定月存模式倒推期數。達標後停止，最後一期不超過尚缺金額。旅遊基金只抵減第一個週期，後續按完整預算預留。
- 環圈只畫非負數；赤字另外明示。七類合計＋其他儲蓄＝收入＋赤字缺口，不能再把環圈、用途分類與子項重複加總。

家庭試算使用稅後輸入，不自行推算所得稅；未提供獎金準備金或實際入帳月份時，不判定各月實際資金已足夠。

### 退休提領與工作收入缺口

退休按年初提領、年末報酬：預定需求為固定名目、隨通膨增加的固定實質，或當期年初資產乘提領率；`實際提領 = min(可用資產, 預定需求)`，`年末資產 = max(0, 年初資產 - 實領) × (1 + 年度報酬)`。實質年末資產以退休起始年購買力折算：`名目年末資產 / (1+通膨率)^年數`。

由每月缺口倒推起始資產的概念式為「月缺口 × 12 ÷ 提領率」，不是保證不耗盡的精算結果。退休預設名目報酬 4%、通膨 2%、提領率 4% 也只是情境。

進階工作月收入需求採：`max(0, 當期生活費＋尚未到期貸款＋額外固定支出＋所選儲蓄投資目標－當期配偶收入－當期已確認其他月收入)`，基本生活情境不加目標，顯示向上取整至元。不使用已先截成 0 的基本結果再加目標，避免收入已有餘裕時高估需求。

### 共同風險聲明

固定報酬曲線無法反映實際市場波動、長壽及極端風險。4% 法則不是股息率，不保證臺股 ETF 或任何資產組合都能安全退休。未納入稅費、交易成本、管理費及完整個人條件；ETF 不保本，也不保證優於銀行。本站不提供個別證券買賣指示、給付資格認定或保證報酬。

## 資料儲存、隱私與第三方服務

- **瀏覽器端運算：** 原始碼沒有傳送家庭表單至後端、GitHub 或 AI API 的流程；不把財務輸入放入分享網址。開啟網站仍會向 Netlify 下載靜態資源，外部資料來源連結亦會前往其網站，這不等於財務表單自動上傳。
- **家庭本機暫存：** 家庭預算的合理值、分類、模式及安全自評使用同一瀏覽器、同一網站來源的 `localStorage` 保存；不是加密保險箱。瀏覽器／裝置不同不會同步，拒絕儲存時仍可試算。「清除已儲存資料」會移除該網站的家庭記錄並重設表單，再次編輯才重新暫存。
- **其他暫態資料：** 目標、複利、退休與進階規劃主要保留在 React 頁面記憶；工具導覽切換可保留當次表單，重新整理或返回所有工具後重建頁面會清除未儲存狀態。家庭頁可從本機暫存恢復；已帶入退休的家庭快照是當次副本，清除家庭暫存不會自動抹除已複製的文字或另一頁快照。
- **主動分享：** 點擊複製後，使用者自行貼到 ChatGPT／Gemini 才將內容交給該第三方；其隱私、保存、訓練及帳號政策由使用者所選服務決定，本專案無法代為保證。請先檢查自由文字、家庭收入與責任資料，移除不想分享的內容。
- **共用裝置：** 使用後清除家庭暫存、剪貼簿及外部 AI 對話中不需保留的資料。不要在程式碼、Issue、PR、網址或截圖放入真實個人財務資料、帳密或 API 金鑰。

## 本機開發與驗證

建議使用 `.nvmrc` 指定的 **Node.js 24** 與 npm；`package.json` 的最低引擎要求為 Node 22.12 以上，驗收及 CI 使用 Node 24。

```sh
git clone https://github.com/Kelly-notebook/financial-literacy-lab.git
cd financial-literacy-lab
git switch feat/savings-comparison
npm ci
npm run dev
```

開啟終端顯示的開發網址，預設為 `http://localhost:5173`。正式版建置及本機預覽：

```sh
npm run build
npm run preview
```

完整驗證方式：

```sh
npm test
npm run format:check
npm run build
npx playwright install chromium
npm run test:e2e
```

環境已有 Chromium 時可改用：

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

Playwright 預設啟動 4173 埠的測試開發伺服器，包含 1440px 桌機與 375px 手機，部分案例另外驗證 320px；同一時間只跑一個會管理此伺服器的測試程序，避免前一輪關閉共用伺服器。卡片元件 fixture 僅供測試，不是正式入口、不會加入 `dist/`。

以上是可重現命令，不代表每個環境都已執行成功；當次結果以 CI 與 PR 的驗收紀錄為準。本文件不固定宣稱測試數量，以免後續修改後失真。`npm run format` 會改寫格式，檢查請使用 `format:check`。

## 分支、自動部署與穩定版本

- `feat/savings-comparison`：目前開發與發布準備分支。
- `main`：待本次 PR 核准後的正式分支，本次準備工作不直接修改或合併它。
- `v0.1.0-stable`：既有穩定 Tag，保留且不覆寫。
- `v1.0.0`：尚待維護者批准，應指向最後核准的正式版本 Commit，不在準備階段提前建立。

既有 Netlify 專案為 `financial-literacy-lab-preview`，沿用原網址。已確認 GitHub 推送開發分支可觸發自動建置；一般 Commit 不加入跳過部署標記。**GitHub 已推送與網站已更新必須分別確認**，以 Netlify 的實際 published commit 為準，而非只看建置開始或其他預覽部署。

發布準備流程為：文件及必要修正 → 完整驗證 → 推送開發分支 → 建立到 `main` 的 PR → 維護者確認。只有確認後才合併、建立正式 Tag、將既有 Netlify Production branch 切到 `main` 並進行最後網站驗收；不建立新 Repository 或新 Netlify 網站，也不刪除開發分支。

`.github/workflows/ci.yml` 是品質檢查，不是 GitHub Pages 或 Netlify 發布 workflow。部署由既有 Netlify Git 連線負責；Vite 使用相對資源路徑。
